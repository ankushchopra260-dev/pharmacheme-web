Every analytics, soft-sensor or AI project in a plant starts with the same question: where is the data? Usually the answer is the process historian, and the quality of that historian decides whether the project takes weeks or years. This article explains what a historian stores, how to name and describe tags, how compression can silently delete the spike you need, why clocks matter, and what changes when the data is GMP.

What a process historian does Basics

The DCS shows what is happening now. A process historian remembers it: every temperature, pressure, flow, level, valve position and alarm, time-stamped, for years. In the ISA-95 picture of a plant it sits between control (level 2) and manufacturing operations (level 3), and it is the data source under almost every analytics and AI project.

  • Troubleshooting: overlay last night’s trend on a good batch.
  • Investigations: evidence for deviations and incidents (see deviations and CAPA).
  • Performance: cycle time, energy and utility consumption, OEE.
  • Models: training data for soft sensors, predictive maintenance and digital twins.

Tags: names, units and context Basics

Each measured value is a tag. A historian with 20,000 tags called AI_1047 is almost useless; one with consistent names is a goldmine. A practical tag record holds:

Compression: how much detail is kept Working level

Storing every value every second for every tag is expensive, so historians discard points that add no information. Deadband (exception) compression discards small changes within a set band; it suits stepwise signals such as valve positions and levels. Swinging door compression keeps the points needed to represent the shape of a smooth signal, and is better for continuous data such as pressure and temperature. Set the band too wide and short spikes (the ones investigations need) disappear.

Time, quality flags and context Working level

  • One clock. DCS, PLCs, historian, MES and LIMS must be synchronised to a common time source. A five-minute offset between the lab and the historian ruins soft sensors and confuses investigations.
  • Quality flags. A good historian stores whether a value was good, bad (instrument fault) or substituted. Analytics must exclude bad values, not treat them as real.
  • Batch context. Store batch ID, product and phase (charging, reaction, distillation) as events, so trends can be aligned batch by batch. This is usually supplied by the MES or the DCS batch engine (see MES and electronic batch records).

Historians in GMP plants Going deeper

When historian data is used for GMP decisions, such as proving a critical process parameter stayed in range, it is a GMP record. FDA’s data integrity guidance (December 2018) expects such records to be attributable, legible, contemporaneously recorded, original or a true copy, and accurate, and 21 CFR Part 11 expects validated systems, secure time-stamped audit trails and controlled access. In practice: validate the interfaces for GMP tags, protect compression settings and tag changes under change control, and keep data for the retention period your quality system requires.

Mistakes I see most often

  • Tag names that do not match the P&ID, so nobody can find the right signal.
  • Default compression on every tag, so short pressure spikes vanish from investigations.
  • Clocks drifting apart between historian, MES and LIMS.
  • Collecting data with no batch context, so batches cannot be compared.
  • Changing compression or scaling on GMP tags without change control.

Questions people ask

What is a process historian?

A database designed to store time-stamped process data (temperatures, pressures, flows, valve positions, alarms) from the DCS and PLCs for years, so trends can be reviewed, compared and analysed.

What compression setting should I use in a historian?

It depends on the signal: tight enough to keep the detail investigations and models need (short spikes, fast changes), loose enough to save storage. Deadband suits stepwise signals; swinging door suits smooth continuous signals. Critical GMP tags deserve deliberate, controlled settings, not defaults.

Is historian data a GMP record?

When it is used to make or support a GMP decision, such as showing a critical process parameter stayed in range, yes. It then needs data-integrity controls: validated interfaces, audit trails, access control and change control.
