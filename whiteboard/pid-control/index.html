PID Control: Whiteboard Lesson

Six questions on control loops: why P-only leaves an offset, what too much gain does, why flow loops skip derivative, which way valves should fail, cascade control and integral windup. Pick an answer, hear what Bubbles thinks of it, then watch the whiteboard explain it. Turn the sound on; there are captions too.

The six questions and answers

The same lesson as text, for reading or revision. More lessons: all whiteboard lessons. More interview questions: Interview Prep.

A P-only level loop settles a little below set point. What removes that offset?

A proportional-only controller changes output in proportion to error, so after a load change it needs a standing error to hold the new valve position, and the process settles off set point. Integral action adds up the error over time and keeps moving the output until the error is zero. Most process loops are PI.

You keep raising the controller gain to make a loop faster. What happens in the end?

Raising controller gain makes a loop respond faster, but past a point it overreacts and oscillates around set point, and can become unstable. Low gain is slow; good gain gives a quick response with a small, settling overshoot. If a loop cycles, put it in manual: if the cycling stops, look at tuning or a sticking valve; if it continues, the disturbance is coming from upstream.

Why do most flow loops run without derivative action?

Flow measurements are noisy, and derivative action responds to the rate of change, so each jitter produces a large output kick. The valve then twitches constantly, wearing it out and making control worse. Flow and pressure loops are usually PI; derivative is mainly useful on slow loops with clean signals, such as some temperature loops.

Cooling water valve on the jacket of an exothermic reactor. Which way should it fail on loss of air?

Choose each valve's failure position by asking what is safe if the air or signal is lost. On an exothermic reactor, losing cooling is the danger, so the jacket cooling water valve fails open. Steam or heating valves fail closed so heat stops, and dosing valves fail closed so addition stops. Confirm each fail position in the HAZOP, since overcooling can be a hazard on some batches.

In a cascade for reactor temperature, which loop is the inner (slave) loop?

In a reactor temperature cascade, the outer (master) loop controls batch temperature and its output is the set point of the inner (slave) loop, which controls jacket temperature by moving the valve. The fast inner loop corrects upsets such as cooling water temperature changes before the batch feels them. Tune the inner loop first; it must be several times faster than the outer loop.

A valve sits at 100 % for a long time, then the PV overshoots badly. What is this?

When a valve is saturated, for example fully open, and the process still cannot reach set point, integral action keeps accumulating error and the controller output winds up far beyond its limit. When the process variable finally reaches set point, the integral must unwind before the valve moves, so the process overshoots. Anti-windup clamps the integral at the output limit; check it is enabled.
